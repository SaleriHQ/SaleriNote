### 1. Flex 布局中父容器属性和子元素属性分别有哪些？

#### 我的回答

> [!question]
>flex 的父容器属性有：
> - flex-direction
> - justify-content
> - align-items
> - align-self
> 
> flex 的字元素有：
> - flex-shrink
> - flex
> - flex-grow
#### 正确回答

> [!success]
> 
>  父容器元素
> - `flex-direction`: 主轴方向
> - `flex-wrap`: 换行方式
> - `flex-flow`: `flex-direction` 和 `flex-wrap` 的简写
> - `justify-content`: 主轴对齐方式
> - `align-items`: 交叉轴对齐方式（单行）
> - `align-self`: 交叉轴对齐方式（多行）
> - `gap`: 项目间距
> 
> 子容器元素
> - `flex-grow`: 放大比例
> - `flex-shrink`: 缩小比例
> - `flex-base`: 初始大小
> - `flex`: `gorw` + `shirnk` + `base` 的简写
> - `align-self`: 单独覆盖交叉轴对齐
> - `order`: 排列顺序
### 2. 分析以下代码的执行结果：

```js
var x = 4, y = 5;
{
	let x = 1;
	const y = 2;
}
console.log(x, y);
```

#### 我的回答

> [!question]
> 4，2。因为 let x 定义的是局部变量所以不会越界，const会
#### 正确回答

> [!success]
> 结果是4, 5
> 关键的点在于 `let` 和 `const` 定义的是块级作用域的变量
> 但是 `var` 定义的是全局作用域的变量

> [!tip]
> `const` 定义的是 **不可重新绑定的变量**，而不是绝对常量，如果定义基本值类型的话值确实不可改变，但是如果是引用类型，不可改变的是指针，但是属性和元素可以改变
### 3. 分析以下浅拷贝代码执行后 `original` 和 `newOne` 的属性变化：

```js
const original = {
	name: '小张',
	age: 20,
	address: {
		city: '武汉',
		street: '武昌',
	}
};
const newOne = { ...original };
newOne.name = '小李';
newOne.age = 30;
newOne.address.city = '武汉';
```
#### 我的回答

> [!question]
> newOne指向的是original的值，所以改变也会同时改变newOne的内部元素的值。
#### 正确回答

> [!success]
> 结果是original.address.city被修改成了武汉，而其他的属性两个变量各自独立
> 关键点在于 JS 的拷贝，这里执行的是 `浅拷贝` ， `浅拷贝` 只是拷贝了第一层的属性，而内部的属性依然是共享引用，所以这里的结果只有original.address.city被修改了，因为嵌套的address没有被拷贝，还是共享的

### 5. 分析以下闭包累加器代码的执行结果：

```js
function createAccumulator(initialValue) {
	let sum = initialValue || 0;
	return function(addValue) {
		if (addValue === undefined) return sum;
		sum += addValue;
		return sum;
	};
}
const totalA = createAccumulator(10);
console.log('A1', totalA(5));
console.log('A2', totalA(2));
console.log('A3', totalA());
console.log('A4', totalA(3));
```
#### 我的回答

> [!question]
> A1: 15
> A2: 17
> A3: 17
> A4: 20
#### 正确回答

> [!success]
> 结果为 15, 17, 17, 20
> 本题考察闭包，闭包会连带创建环境一起打包返回，所以对于同一个闭包对象，sum不会被销毁。
### 6. JS 事件循环的执行顺序是什么？
#### 我的回答

> [!question]
> 不知道!!!!
#### 正确回答

> [!success]
> JS 事件执行顺序是 `同步任务` -> `微任务` -> `宏任务`
> 微任务包含
> - Promise.then
> - MutationObserver
> - queueMicrotask
> - async/await
> 
> 宏任务包含
> - setTimeout
> - setInterval
> - setImmediate
> - I/O
> - UI rendering
> ```js
> console.log('1')
> setTimeout(() => console.log('2'), 0)
> Promise.resolve().then(() => console.log('3')
> console.log('4')
> ```
> 对于上面的代码，执行顺序为 1 4 3 2
### 7. 分析以下事件循环代码的执行输出顺序：

```js
console.log('script strat'); // 1 同步
async function async1() {
	console.log('async1 start'); // 2 同步
	await async2();
	// await 后续变为微任务
	console.log('asyn1 end'); // 6 微任务_2
}
async function async2() {
	console.log('async2'); // 3 同步
}

Promise.resolve().then(() => {
	console.log('Promise then1'); // 5 微任务_1
	setTimeout(() => {
		console.log('promise then1 setTimeout'); // 8 宏任务_2
	});
});
setTimeout(() => {
	console.log('settimeout'); // 7 宏任务_1
});

async1();
console.log('script end'); // 4 同步
```
#### 我的回答

> [!question]
> script start
> script end
> async1 start
> async2
> async1 end
> Promise then1
> settimeout
> promies then1 setTimeout
#### 正确回答

> [!success]
> script start
> async1 start
> async2
> script end
> Promise then1
> async1 end
> settimeout
> promise then1 setTimeout
>1.  首先执行最开始的同步输出`script start`
>2.  然后将Promise存入微任务队列
>3.  然后将setTimeout存入宏任务队列，
>4. 输出async1的`async1 start`，`async1 end` 存入微任务队列
>5. 进入async2输出`async2`
>6. 结束async1，输出`script end`
>7. 开始执行微任务队列1，输出`Promise then1`，将setTimeout存入宏任务队列
>8. 执行微任务队列2，输出`async1 end`
>9. 执行宏任务队列1，输出`settimeout`
>10. 执行宏任务队列2，输出`promise then1 setTimeout`
